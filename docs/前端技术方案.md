# 前端技术方案文档

## 一、项目概述

本项目为"挑战杯"揭榜挂帅赛道参赛作品，旨在构建**新一代信息技术岗位全景图谱与智能人岗匹配系统**。前端负责将后端的大模型抽取、知识图谱构建、人岗匹配等能力以可视化、可交互的方式呈现给用户。

### 核心功能模块

| 模块 | 功能描述 |
|------|----------|
| 岗位全景图谱可视化 | 基于 Three.js 的 3D 星图，展示岗位-技能-知识三维关系 |
| 人岗匹配界面 | 简历上传 → 解析 → 匹配 → 差距分析的完整流程 |
| JD 管理 | 岗位描述上传（文本/OCR）、解析、画像查看 |
| 技能差距分析 | 清晰展示候选人与目标岗位的技能缺失项 |

## 四、页面设计

### 4.1 Dashboard（首页概览）

**功能：**
- 系统状态监控（后端健康检查、OCR/LLM/Neo4j 可用性）
- 数据概览卡片（JD 数量、简历数量、匹配次数）
- 3D 岗位技能星图入口
- 快速操作导航

**技术要点：**
- 调用 `GET /health` 和 `GET /api/v1/capabilities` 获取系统状态
- 使用 Ant Design `Statistic` 组件展示指标
- 预留 JobGalaxy 3D 星图渲染区域

### 4.2 JD 管理

**功能：**
- 文本输入创建 JD 文档
- OCR 上传图片/PDF 自动识别
- JD 列表展示（分页、搜索）
- 一键生成岗位画像
- 查看画像详情（技能、知识、要求）

**数据流程：**
```
用户输入 JD 文本
    │
    ▼
POST /api/v1/documents  ──→  创建文档资源
    │
    ▼
POST /api/v1/job-profiles  ──→  调用 Ollama 抽取画像
    │
    ▼
GET /api/v1/job-profiles/{id}  ──→  展示画像详情
```

**技术要点：**
- 支持 `multipart/form-data` 上传（OCR）
- 画像结果以 JSON 格式展示，支持折叠/展开
- 画像状态为 `mock` 时显示警告提示

### 4.3 简历管理

**功能：** 与 JD 管理类似，但 `document_type` 为 `resume`，画像接口为 `candidate-profiles`。

### 4.4 人岗匹配

**功能：**
- 左右分栏输入简历和 JD 文本
- 一键匹配（自动完成：创建文档 → 生成画像 → 执行匹配 → 生成报告）
- 匹配得分仪表盘（Progress 环形图）
- 匹配维度雷达图（ECharts Radar）
- 匹配详情 JSON 展示
- 匹配报告文本展示

**数据流程：**
```
简历文本 + JD 文本
    │
    ├─→ POST /documents (resume)  ──→  简历文档
    ├─→ POST /documents (jd)      ──→  JD 文档
    │
    ├─→ POST /candidate-profiles  ──→  候选人画像
    ├─→ POST /job-profiles        ──→  岗位画像
    │
    ├─→ POST /matches             ──→  匹配结果（含 score）
    │
    └─→ POST /reports             ──→  匹配报告
```

**技术要点：**
- 使用 `message.loading` 展示匹配进度
- 雷达图使用 ECharts `radar` 类型
- 得分颜色映射：≥80 绿色、≥60 橙色、<60 红色

### 4.5 知识图谱

**功能：**
- ECharts 关系图展示岗位-技能-知识-能力网络
- 节点可拖拽、点击高亮相邻节点
- 图谱 RAG 检索问答
- 图谱构建触发

**技术要点：**
- 使用 ECharts `graph` 类型，`layout: "force"` 力导向布局
- 四类节点：岗位（蓝）、技能（绿）、知识（紫）、通用能力（橙）
- RAG 检索调用 `POST /data-governance/rag/answer`

## 六、3D 可视化方案（复用 JobCloud）

### 6.1 JobGalaxy 星图

JobCloud 的 `JobGalaxy` 组件使用 Three.js 实现三层 3D 星图：

```
        ┌─────────────────────────────────────┐
        │         Layer 1: 岗位大类            │  y = 26
        │   [前端] [后端] [算法] [测试] ...     │
        └─────────────────┬───────────────────┘
                          │ 连线
        ┌─────────────────┴───────────────────┐
        │         Layer 0: 职位                │  y = 0
        │   [Python开发] [Java开发] [测试工程]  │
        └─────────────────┬───────────────────┘
                          │ 连线
        ┌─────────────────┴───────────────────┐
        │         Layer -1: 技能               │  y = -26
        │   [Python] [MySQL] [Linux] [Docker]  │
        └─────────────────────────────────────┘
```

**核心特性：**
- 节点大小映射技能频次
- 节点颜色映射热度（绿→黄→红）
- 点击节点高亮相邻关系
- 支持鼠标拖拽旋转、缩放
- 自定义 Shader 实现粒子发光效果

### 6.2 复用策略

| JobCloud 文件 | 复用内容 | 改动点 |
|---------------|----------|--------|
| `jobGraph.js` | 图数据构建、技能提取、分类规则 | 替换数据源为后端 API 返回 |
| `JobGalaxy.jsx` | Three.js 场景、渲染、交互 | 接入后端图谱数据 |
| `SkillDag.jsx` | 技能 DAG 布局 | 适配新的技能分类体系 |
| `skillDag.js` | DAG 模型构建 | 扩展 L/S/K/T/Tech 五类 |

### 6.3 数据适配

JobCloud 的输入格式：

```json
[
  {
    "job_id": "40857992907",
    "title": "Python自动化测试工程师",
    "description": "...",
    "requirement": "..."
  }
]
```

后端 JD 数据格式（`jd_raw.jsonl`）：

```json
{
  "job_id": 40857441205,
  "job_title": "(CDU/AI服务器机柜）机构设计资深工程师",
  "jd_text": "岗位职责：...",
  "skills_raw": ["AI服务器", "SolidWorks", "水冷", "液冷"],
  "skills_norm": ["AI服务器", "SolidWorks", "水冷", "液冷"]
}
```

需要编写适配层将后端数据转换为 JobCloud 的输入格式。

**技术细节：**

```js
// P0-1: 数据适配层示例
// src/adapters/jobGraphAdapter.js

/**
 * 将后端 jd_raw.jsonl 数据转换为 JobGalaxy 所需格式
 * @param {Array} backendData - 后端返回的 JD 数组
 * @returns {Object} { nodes, links, categories }
 */
export function adaptJobData(backendData) {
  const nodes = [];
  const links = [];
  const categories = [
    { name: '岗位大类' },
    { name: '职位' },
    { name: '技能' }
  ];

  backendData.forEach(jd => {
    // 岗位节点
    nodes.push({
      id: `job_${jd.job_id}`,
      name: jd.job_title,
      category: 1,
      value: jd.skills_norm?.length || 0,
      symbolSize: Math.max(10, (jd.skills_norm?.length || 0) * 3),
    });

    // 技能节点与连线
    jd.skills_norm?.forEach(skill => {
      const skillId = `skill_${skill}`;
      if (!nodes.find(n => n.id === skillId)) {
        nodes.push({
          id: skillId,
          name: skill,
          category: 2,
          value: 1,
          symbolSize: 8,
        });
      }
      links.push({
        source: `job_${jd.job_id}`,
        target: skillId,
      });
    });
  });

  return { nodes, links, categories };
}
```

// src/components/GraphView.jsx

const highlightRagResults = (graph, searchResults) => {
  const { nodes, edges } = graph;
  const resultNodeIds = new Set(searchResults.map(r => r.node_id));

  // 更新节点样式
  nodes.forEach(node => {
    if (resultNodeIds.has(node.id)) {
      node.itemStyle = {
        borderColor: '#ff6b6b',
        borderWidth: 3,
        shadowBlur: 10,
        shadowColor: '#ff6b6b',
      };
      node.label = {
        show: true,
        fontSize: 14,
        fontWeight: 'bold',
      };
    } else {
      node.itemStyle = { opacity: 0.3 };
    }
  });

  // 高亮相关边
  edges.forEach(edge => {
    if (resultNodeIds.has(edge.source) || resultNodeIds.has(edge.target)) {
      edge.lineStyle = {
        color: '#ff6b6b',
        width: 2,
        type: 'solid',
      };
    }
  });

  return { nodes, edges };
};

import html2canvas from 'html2canvas';

export async function generateMatchReport(matchData, chartsRef) {
  const pdf = new jsPDF('p', 'mm', 'a4');

  if (chartsRef.radar) {
    const radarCanvas = await html2canvas(chartsRef.radar);

    pdf.addImage(radarImg, 'PNG', 20, 55, 170, 100);
  }

  pdf.addPage();
  pdf.setFontSize(16);
  pdf.text('技能差距分析', 20, 20);

  // 5. 保存
  pdf.save(`匹配报告_${matchData.id}.pdf`);
}
