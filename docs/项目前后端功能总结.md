# 岗位—能力图谱系统：前后端功能总结

## 一、项目概述

本系统是一个**基于大模型与知识图谱的智能人岗匹配平台**，面向新一代信息技术岗位。用户上传岗位描述（JD）和候选人简历后，系统自动提取技能画像、执行人岗匹配、生成差距分析报告，并通过知识图谱可视化展示岗位—技能—知识—能力的关系网络。

---

## 二、后端（FastAPI + Python）

后端采用 **DDD 分层架构**（domain → application → infrastructure → api），核心入口为 `backend/app/main.py`，API 基础路径为 `/api/v1`。

### 2.1 模块总览

| 模块 | 路径 | 功能说明 |
|---|---|---|
| 文档管理 | `api/v1/routes/documents.py` | 创建 JD/简历文档（文本输入或 OCR 图片/PDF 识别），文档原文不回显 |
| 画像提取 | `api/v1/routes/profiles.py` | 从文档生成候选人画像（`candidate-profiles`）和岗位画像（`job-profiles`） |
| 人岗匹配 | `api/v1/routes/intelligence.py` | 创建匹配（`/matches`）、生成匹配报告（`/reports`）、知识图谱构建与检索 |
| 数据治理 | `api/v1/routes/data_governance.py` | 文件级数据治理链路：注册 → 处理 → LSKT span 抽取 → ESCO 概念链接 → 证据绑定 → 图谱 JSON → RAG 检索 |
| 系统信息 | `api/v1/routes/system.py` | 健康检查（`/health`）、能力状态（`/capabilities`） |

### 2.2 核心能力

#### 文档管理
- **文本输入**：直接提交 JD/简历原文，创建文档
- **OCR 识别**：上传图片或 PDF，基于 PaddleOCR（CPU 版）识别文本，支持中文
- **批量上传**：支持多文件批量 OCR 识别
- **安全设计**：响应仅返回文档元数据、长度和摘要校验值，不回显原文

#### 画像提取
- **候选人画像**（`CandidateProfile`）：从简历中提取技能、经验、教育等结构化信息
- **岗位画像**（`JDProfile`）：从 JD 中提取岗位要求、技能需求等结构化信息
- **LLM 支持**：可对接本地 Ollama 模型（qwen2.5:7b）做结构化抽取，模型不可用时自动降级为 mock

#### 人岗匹配
- 接收候选人画像 ID 和岗位画像 ID，执行多维度匹配打分
- 匹配维度包括：技能匹配、知识匹配、经验匹配、通用能力
- 生成匹配报告，支持中英文

#### 知识图谱
- 构建岗位—技能—知识—能力关系图谱
- 可选 Neo4j 后端持久化存储（`GRAPH_BACKEND=neo4j`）
- 支持图谱路径检索（`graph-retrievals`）

#### 数据治理
- 文件级数据治理链路，建立 `doc_id → chunk_id → version → evidence` 追溯链
- LSKT 能力分类：K（知识/理论）、S（可执行技能）、T（通用能力）、L（语言能力）
- ESCO 概念链接：将抽取的 span 链接到官方 ESCO 能力本体索引
- RAG 检索：基于治理后的 chunk 索引进行检索问答

### 2.3 基础设施

| 组件 | 路径 | 说明 |
|---|---|---|
| OCR 适配器 | `infrastructure/ocr/paddle_adapter.py` | PaddleOCR 文档识别 |
| LLM 适配器 | `infrastructure/llm/` | Ollama 本地模型对接、prompt 管理、输出解析与归一化 |
| Neo4j 适配器 | `infrastructure/neo4j/adapters.py` | 知识图谱持久化存储 |
| Mock 适配器 | `infrastructure/mocks/adapters.py` | 智能接口的 mock 降级实现 |
| 内存仓库 | `infrastructure/memory/repositories.py` | 进程内资源管理（重启清空） |
| 依赖注入 | `infrastructure/wiring.py` | 容器构建与依赖组装 |

### 2.4 关键设计决策

1. **Mock 降级策略**：所有智能接口（画像、匹配、图谱）默认使用 mock，模型不可用时服务不中断，响应 `warnings` 字段说明原因
2. **证据约束**：每个候选 span 必须能从原文按 `start_char/end_char` 切回，evidence quote 必须包含该 span
3. **ESCO 索引**：不再维护运行时手写技能词表，使用官方 ESCO 快照索引（`data/esco`）

## 三、前端（React + Ant Design + ECharts）

前端是一个**深色主题的单页应用**，技术栈为 React 18 + Ant Design 5 + ECharts + Zustand。

### 3.1 页面路由

| 页面 | 路径 | 功能说明 |
|---|---|---|
| 数据概览 | `/` | 系统状态（健康检查、OCR/图谱/LLM 可用性）、统计数据、3D 岗位星图、快速操作入口 |
| JD 管理 | `/jd` | 上传岗位描述：文本输入 / 单文件 OCR / 批量 OCR，支持 OCR 校正，可生成和查看岗位画像 |
| 简历管理 | `/resume` | 上传候选人简历：功能同 JD 管理，生成候选人画像 |
| 人岗匹配 | `/match` | 输入简历+JD → 一键匹配，展示雷达图、技能差距分析、匹配得分，支持导出报告 |
| 匹配历史 | `/history` | 查看历史匹配记录，支持详情查看、导出、两两对比 |
| 知识图谱 | `/graph` | 力导向图展示关系网络，支持 RAG 检索高亮、分类筛选、节点搜索、导出 |
| 系统设置 | `/settings` | 主题/主色调/侧边栏/图表配色等偏好设置 |

### 3.2 各页面详细功能

#### Dashboard（数据概览）
- **系统状态卡片**：实时展示后端健康状态、OCR 识别可用性、知识图谱可用性、LLM 抽取可用性
- **统计卡片**：总匹配次数、平均匹配度、文档总数、系统可用性（动画数字）
- **3D 星图**：使用 Three.js 渲染的岗位能力 3D 可视化（`JobGalaxy` 组件）
- **快速操作**：跳转到上传 JD、上传简历、人岗匹配、查看图谱的快捷入口

#### JD 管理 / 简历管理
- **三种上传方式**：
  - 文本输入：直接粘贴原文
  - 单文件 OCR：拖拽或点击上传图片/PDF
  - 批量上传：多文件同时 OCR，带进度条和状态跟踪
- **OCR 校正**：识别完成后弹出校正弹窗，用户可修正 OCR 结果后再入库
- **画像操作**：对已上传文档可「生成画像」或「查看画像详情」
- **文档列表**：表格展示已上传文档的 ID、类型、来源、文本长度

#### 人岗匹配
- **输入区**：左右分栏输入简历文本和 JD 文本
- **一键匹配**：自动完成以下流程：
  1. 创建简历文档
  2. 创建 JD 文档
  3. 生成候选人画像
  4. 生成岗位画像
  5. 执行人岗匹配
  6. 生成匹配报告
- **结果展示**：
  - 匹配得分（大字动画，颜色分级：≥80 高度匹配 / ≥60 较为匹配 / ≥40 部分匹配 / <40 匹配度低）
  - 技能差距图（`GapChart` 组件）
  - 雷达图（ECharts，五维：技能/知识/经验/通用能力/综合）
  - 匹配详情 JSON
  - 匹配报告（文本形式）
- **导出**：支持 TXT / JSON / CSV 三种格式

#### 匹配历史
- **历史表格**：展示时间、匹配得分、简历/JD 摘要、实现方式
- **操作**：查看详情、导出报告、删除记录、清空全部
- **对比功能**：勾选两条记录可并排对比（得分、已掌握技能数、缺失技能数、原始详情）

#### 知识图谱
- **图谱可视化**：ECharts 力导向图，节点分为四类：
  - 岗位（蓝色）、技能（绿色）、知识（紫色）、通用能力（黄色）
- **交互功能**：
  - 节点拖拽、点击高亮相邻节点
  - 搜索框过滤节点
  - 分类筛选（按岗位/技能/知识/通用能力）
  - 导出 JSON / CSV
- **RAG 检索**：输入问题后检索图谱，高亮相关节点，展示回答和引用来源
- **图谱统计**：节点数量、关系数量、分类数量

#### 系统设置
- 主题模式（深色/浅色）
- 主色调选择（冰蓝/翠绿/琥珀/珊瑚/紫罗兰）
- 侧边栏默认收起开关
- 雷达图配色方案展示
- 存储信息说明（localStorage，100 条历史上限）

## 四、前后端交互流程

### 4.1 人岗匹配主流程

```
用户输入简历 + JD 文本
  │
  ├─ POST /api/v1/documents          → 创建简历文档，返回 document_id
  ├─ POST /api/v1/documents          → 创建 JD 文档，返回 document_id
  ├─ POST /api/v1/candidate-profiles → 生成候选人画像，返回 profile_id
  ├─ POST /api/v1/job-profiles       → 生成岗位画像，返回 profile_id
  ├─ POST /api/v1/matches            → 执行人岗匹配，返回 match_id + score + details
  └─ POST /api/v1/reports            → 生成匹配报告，返回报告内容
```

### 4.2 OCR 上传流程

```
用户上传图片/PDF
  │
  ├─ POST /api/v1/documents/ocr      → PaddleOCR 识别，返回文档 + 置信度
  ├─ 用户校正 OCR 结果（前端弹窗）
  └─ POST /api/v1/documents          → 用校正后文本创建文档
```

### 4.3 知识图谱 RAG 流程

```
用户输入检索问题
  │
  ├─ POST /api/v1/data-governance/rag/answer → 检索 + 生成带引用的回答
  └─ 前端根据回答内容高亮图谱中相关节点
```
